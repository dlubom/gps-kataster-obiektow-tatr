# PBI-074 — kontrolowany preflight dat poza zakresem po normalizacji UTC

Status: **planowane — gotowe**, nowy P2 z niezależnego review PBI-054.
Baza: `97428eb9950b0fc8bc42b137c01d6d20525e4161`; zależności 035/040
wykonane. Nie rozpoczęto naprawy.

`best_measurement.py:91–100` łapie ValueError tylko przy fromisoformat.
Normalizacja `parsed.astimezone(UTC)` może wyjść poza zakres datetime:
`9999-12-31T23:59:59-01:00` i `0001-01-01T00:00:00+01:00` są schema-valid,
lecz powodują nieobsłużony OverflowError. Publiczne validate_data_dir,
build_sqlite_database i apply_review_decisions (write=False/True, również
puste decisions) każde przerywają preflight wyjątkiem zamiast kontrolowanej
diagnostyki. 8/8 awarii, schema 0, wejścia i istniejące wyjścia niezmienne.
Kontrola zwykłej daty przechodzi wszystkie cztery API bez ERROR/wyjątku.
Nie wykazano utraty danych ani obejścia blokady zapisu.

Niezależną próbę powtórzył właściciel PBI. Przenośna reprodukcja:

```bash
uv run --frozen python docs/asdlc/verification/PBI-054-datetime-overflow-probe.py "$PWD"
```

Exit 0 tego skryptu dowodzi odtworzenia obecnej usterki. Pełne stdout,
traceback, niezmienność i SHA są w PBI-054-final-artifacts.json.

Odbiór: RED obu granic na publicznym preflight, GREEN po naprawie,
diagnostyka związana z właściwym pomiarem i brak zapisów błędnej partii.
UTC/Z, offsety dodatnie/ujemne, zwykłe daty i legalne skrajne daty bez
przepełnienia muszą zachować wybór najlepszego pomiaru. Sprawdzić podobne
normalizacje dat w staging/buildzie; nie rozszerzać schema bez decyzji
specyfikacyjnej. Pełna bramka, mutacje zmienionego obszaru, niezależny
review, scoped commit/push i exact-SHA CI. Następnie ponowić 054 na nowej
generacji, bez sumowania tej kampanii.
