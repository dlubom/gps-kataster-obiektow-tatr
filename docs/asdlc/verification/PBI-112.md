# PBI-112 — audyt dokładności i spójności eksportów v1.2.0

## Wynik

**Paczka nie spełnia zatwierdzonego warunku rozdzielenia punktów o ponad 1 m ani unikalności nazw obiektów.** Audyt wykrył 16 par (29 różnych obiektów) w odległości ≤ 1 m i jedną parę o tej samej nazwie. Nie jest to dowód tożsamości obiektów ani podstawa do automatycznego scalenia. Dane katalogu nie zostały zmienione.

Identyfikatory obiektów/jaskiń i pomiarów są unikalne na właściwych poziomach. Wszystkie nazwy są niepuste. Nie znaleziono braków wymaganych tagów TPN, referencji GLOBALID ani numerów jaskiń PIG; żaden GLOBALID nie należy do dwóch obiektów.

## Źródło i metoda

- [Publiczne wydanie v1.2.0](https://github.com/dlubom/gps-kataster-obiektow-tatr/releases/tag/v1.2.0), opublikowane 2026-10-23 15:08:50 UTC; commit caf7bae69b28eb037810215889cb87f763b2c6bd (tag i statistics.json zgodne).

- Czytnik [audit_release_data.py](../../../scripts/audit_release_data.py) nie importuje kodu eksportera ani nie wybiera ponownie best. Źródłem pełnego modelu jest SQLite odczytane z publicznego ZIP-a w trybie tylko do odczytu. Pozostałe pliki są czytane niezależnie.
- Best: jeden wiersz na object_id. Full: klucz object_id/measurement_id. Ta sama jaskinia i jej numer przy kilku otworach są prawidłowe.
- Wszystkie 506 521 nieuporządkowane pary wybranych punktów porównano geodezyjnie na elipsoidzie WGS84, z pełnej precyzji SQLite, próg ≤ 1,000 m, bez zaokrąglania. Równość par WGS84 i PL-1992 sprawdzono osobno.
- Nazwy: porównanie dokładne i po NFC/casefold/normalizacji białych znaków; polskie znaki, interpunkcja i oznaczenia otworów zachowane.
- Pochodzenie: referencje obiektu/jaskini i cała historia, a nie wyłącznie source wybranego pomiaru. UUID porównano po ujednoliceniu wielkości liter i klamer.
- Pełny wynik i zakres każdej kontroli: [report.json](PBI-112/report.json). Wszystkie ustalenia z wartościami, nazwami, ID i lokalizacją: [findings.csv](PBI-112/findings.csv).

## Zakres porównania formatów i ograniczenia

- CSV i GeoJSON: wszystkie wspólne pola; dodatkowo geometria GeoJSON. GPX: ID, pomiar, etykieta, rodzaj, współrzędne, wysokość, czas i pełny opis ze źródłem, datą i uwagami. Shapefile: wszystkie 20 pól DBF i geometria.
- Excel: 1007 wierszy Best (13 kolumn) oraz 1908 Full (56 kolumn), także tagi, referencje, historia, wybór, autorstwo, załączniki i relacje. Dane zaczynają się od wiersza 7 w obu arkuszach. Sprawdzono wersję/commit/czas we właściwościach pliku oraz 5830 geometrii WKT w SQLite (pomiary i cache obiektów).
- Tolerancja CSV/GPX: 5,1×10⁻¹¹ stopnia; DBF: 5,1×10⁻⁹ stopnia, 0,00051 m dla XY i 0,00501 m dla wysokości. Dopełnienie pól tekstowych DBF i udokumentowane obcięcie notatek do 254 bajtów nie stanowią nowych błędów; pełna treść pozostaje w innych formatach.
- **Wszystkie 1007 wybranych punktów mają nieznaną deklarowaną dokładność poziomą.** Nie jest to zero błędu. Brak niezależnych punktów pomiarowych uniemożliwia oszacowanie rzeczywistej dokładności terenowej.
- **34 wybrane wysokości pochodzą z DEM.** Są oznaczone i mają opis źródła; nie potwierdzają wysokości otworu. Układ wysokości jest unknown dla 1005 punktów i Kronstadt86 dla dwóch. Audyt nie przelicza datum pionowego ani nie pozyskuje nowych wysokości.
- Audyt jest przekrojowy dla jednego wydania; nie bada trendów ani kompletności źródeł PIG/TPN względem rzeczywistości. Brak duplikatów ID i numerów nie dowodzi braku semantycznie zdublowanych jaskiń pod innymi oznaczeniami.

## Odtworzenie

Pobrać dokładne pliki wskazane w manifest.json do nowego katalogu; zachować przypięte metadane release.json (bieżące liczniki pobrań GitHub mogą się zmieniać). Przykład:

```sh
mkdir -p build/audits/replay/source
gh release download v1.2.0 --dir build/audits/replay/source
cp docs/asdlc/verification/PBI-112/release.json build/audits/replay/source/release.json
uv run --frozen python scripts/audit_release_data.py \
  --input-dir build/audits/replay/source \
  --output-dir build/audits/replay/result \
  --source-commit caf7bae69b28eb037810215889cb87f763b2c6bd
```

Wyjście 0 oznacza wykonanie audytu. Stan danych wynika z checks/summary w report.json. Niezgodność SHA-256 lub nieobsługiwany schemat przerywają audyt; nie są zastępowane wynikiem spełnionym.
