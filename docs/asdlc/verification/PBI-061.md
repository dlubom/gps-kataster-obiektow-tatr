## Odtworzenie i skutek

Sekcja `finite_dbf_elevation`: poprawny obiekt z `elevation_m=1e50`
albo `-1e50`; 0 błędów walidacji, build sukces, SQLite przechowuje
odpowiednio 1e50/-1e50. DBF `elev_m` (`F`, szerokość 50, 2 miejsca)
cicho obcina końcówkę zapisu stałoprzecinkowego:

| Wejście | Odczyt SQLite | Odczyt DBF |
|---|---|---|
| 2**63 (kontrola PBI-055) | 9.223372036854776e18 | 9.223372036854776e18 |
| 1e49 (kontrola) | 1e49 | 1e49 |
| 1e50 | 1e50 | 1.0000000000000001e49 |
| -1e50 | -1e50 | -1e48 |

Dla 1e50 surowe pole to
`10000000000000000762976984109188700329496497094656`, bez ostatniej
cyfry części całkowitej. PyShp 3.0.3 zapisuje
`format(float(value), ".2f")[:size]`. Eksporter przekazuje liczby do
`writer.record` bez kontroli szerokości (`best_measurements_export.py:319`,
`393`, `593–598`). To ograniczenie reprezentacji formatu, nie żądanie
fizycznego limitu wysokości/dokładności ani zmiany źródłowego YAML.
