## Implementacja i kontrakty

- `yaml_paths.py` udostępnia wspólne rozpoznawanie plików i numerów.
  Loader zachowuje dotychczasową kolejność, rekurencję i oba rozszerzenia;
  publiczny import `data_loader.iter_yaml_paths` pozostaje dostępny.
  `assign_id` i helpery obu importerów korzystają z tej samej polityki.
  Katalog o nazwie `KSW-99999.yml` nie rezerwuje numeru; `.bak` i pliki
  innego prefixu nie wpływają na licznik. Licznik nadal może przekroczyć 9999.
- Review przechowuje osobne mapy ID → oryginalna ścieżka dla obiektów
  i jaskiń. `add_measurement` i `link_cave` korzystają z nich podczas
  zapisu, również dla starej jaskini. Nowe rekordy używają `.yml`.
- Indeksowanie sprawdza powtórzone ID przed zastąpieniem wpisu słownika.
  Konflikt obu rozszerzeń (identyczna lub różna treść) daje
  `FINAL_DATA_INVALID` z ID i obiema ścieżkami; cała partia pozostaje
  bez zapisów i bez zastosowanych decyzji, także w dry-run.
- Numeracja jest propozycją tylko do odczytu: dwa rozszerzenia tego samego
  numeru rezerwują go, ale nie wymuszają wyboru pliku. Dopiero próba review
  takiego katalogu jest blokowana jako niejednoznaczna.
- Przenośne testy obejmują mieszany katalog, aktualizację pomiaru,
  przeniesienie A→B, zachowanie historii oraz bajtów nietkniętych plików,
  nowe `.yml` obok istniejących `.yaml`, konflikt i numery 1/9999/10000.
- Test podkatalogów rozróżnia odkrywanie i walidację: loader znajduje
  takie rekordy, ale istniejąca reguła kanonicznej ścieżki nadal daje
  `FILE_ID_MISMATCH`. Test sprawdza zachowanie oryginalnych ścieżek i tych
  samych błędów. Nie uznaje niekanonicznego katalogu za poprawny; blokada
  błędnego wejścia w samym review pozostaje zakresem PBI-040.
- Specyfikacja §5.6 i dokument decyzji review opisują nowy kontrakt.
  Nowy krytyczny helper oraz regresje weszły do konfiguracji mutmut.
