## Zakres

`tpn-sync.yml` dodaje wyłącznie workflow_dispatch prepare/apply/refresh.
Odczyt przygotowuje kompletny snapshot, porównanie, pending i bundle Git;
osobny job z contents/pull-requests write odtwarza dane i publikuje zwykłym
push. Kod oraz zależności obu jobów pochodzą z dokładnego SHA main.
Przy apply PR dostarcza tylko regularne pliki danych, nigdy kod do wykonania.

Jeden otwarty PR w repo, wspólny klucz concurrency, ponowna kontrola
main/HEAD/uprawnień. Awaria push→create PR jest odzyskiwana na tej samej
gałęzi. Zamknięcie bez merge nie przesuwa bazy. Apply i jawny refresh
zachowują poprzednie commity bez force-push; ruch main wymaga nowej podstawy
i ponownego review. Refresh zachowuje też nowe, niezależne zmiany main.

Nowe automatic_proposal mogą pokazać YAML z audytem technicznym przy pending;
istniejące/niepewne propozycje nie materializują akcji przed decyzją.
Końcowe decyzje wymagają uprawnionego ludzkiego dispatchera github:LOGIN.
Zwykły check nadal odrzuca pending. Wewnętrzna kontrola publishera może
sprawdzić poprawność pending, ale nie nadaje zgody na merge.

## Nieukończony odbiór produkcyjny

Nie wykonano produkcyjnego dispatch ani nowego PR przez GITHUB_TOKEN.
Przyczyny są konkretne:

1. PR #12/PBI-101 nie został po ludzku zmergowany; workflow oraz przyjęty
   stan źródła nie są jeszcze na main.
2. Live odczyt ustawień Actions: default_workflow_permissions=read,
   can_approve_pull_request_reviews=false. Tworzenie PR przez Actions jest
   wyłączone. Ustawienia nie zmieniono; wymaga osobnej decyzji maintenera.

Odczyt efektywnej ochrony main: wymagany `Validate code and data`, GitHub
Actions app 15368; jedno ludzkie review, rozstrzygnięte wątki, ochrona
przed non-fast-forward i usunięciem. Nie zmieniano tych reguł.

Po spełnieniu warunków operator wykonuje prepare → draft → indywidualne
decyzje → apply w tej samej gałęzi; sprawdza no-op/retry/open PR, czerwone
pending i zielony końcowy wynik, wszystkie checki dokładnego SHA oraz ZIP
i eksporty. Człowiek uruchamia **Approve workflows to run**, zgodnie z
[aktualną dokumentacją GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow).
Sprawdzenie dokumentacji i fixture nie potwierdza jeszcze zachowania
rzeczywistego tokena. Dwa ostatnie kryteria karty pozostają otwarte.
