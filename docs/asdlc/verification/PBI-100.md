## Kryteria i dowody

| Kryterium | Implementacja / scenariusz |
|---|---|
| Ścisły format zmian/decyzji | tpn_batch_protocol: wersja/allowlisty/typy, unikalne klucze YAML, komplet decyzji, pending/approve/reject/defer. Raport odtwarzany z Git/snapshotu, execution/proposals są hashowane. |
| Hashy, rewizje, preimages, konflikty | Nagłówek wiąże snapshot/GUID/revision/cel/katalog/stan/politykę. Approve wymaga jawnych potwierdzeń konfliktów i kandydatów. Nie można podmienić treści źródła przez przeliczenie hasha. |
| Cały obiekt i ID partii | DomainPlan: wspólne rezerwacje ID, kilka GUID jednego Obiektu, wszystkie dodatki razem przed strażnikiem best; sprzeczne akcje są błędem. |
| Historia/wysokości/statusy | Allowlista metadata, dopisywane notes, append-only historia, nowe pomiary nieweryfikowane/unknown accuracy/bez Z; data modyfikacji z komentarzem, brak daty blokuje pomiar. |
| Ochrona best | PBI-099 użyty w łącznym planie oraz ponownie przed publikacją. Manual/GNSS/historia/własne zweryfikowane chronione; pending manifest nie daje migracji. |
| Pełny preflight i awaria zapisu | Pełna walidacja przed/po w pamięci; staged readback; jedna atomowa zamiana całego data na macOS/Linux. Test błędu exchange i przerwania procesu przed/po commit point. |
| Idempotencja i zmiana decyzji | Wynikowe hashe i odbudowa starego planu z archiwum; powtórzenie bez zmian; reject/defer usuwa tylko własną nieedytowaną propozycję. Archiwum zachowuje wcześniejsze rozstrzygnięcia. |
| Bramka pending/defer/diff | Workflow validate sprawdza zmienione paczki i stan; pending/niespójność/brak archiwum blokują; defer przechodzi z trwałą kolejką. Sprawdzenie działa także po własnym ludzkim merge. |
| Dry-run/apply i eksporty | Ten sam plan/diff/best/ID; przed/po rzeczywistego kolektora Best oraz pełnej historii. Test porównuje plan z zapisanym wynikiem i odczytanym CSV. |

Techniczne doprecyzowania: execution/proposals utrwala akcje do zatwierdzenia
bez osłabiania dowodów PBI-097; wszystkie końcowe statusy wiążą wynik całej
partii (wejściowe preimage pozostaje w audycie), aby approve nie unieważniało
od razu defer/reject. Lokalny zaufany operator przekazuje autoryzowane ID
reviewerów; CI nie wywodzi uprawnień człowieka z samego tekstu autora.
GitHub i ludzki merge pozostają granicą przyjęcia. PBI-102 dostarczy
zaufany workflow, obecna karta go nie uruchamia.
