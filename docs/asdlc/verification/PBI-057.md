## Odkrycie i reprodukcja

Ważniejszy wariant używa **poprawnego raportu wygenerowanego przez
`build_pig_staging`**, bez jego edycji. Dwa wiersze CSV PIG: row 1
`PIG:1692` → `KSW-0001`/`C-0001`, row 2 `PIG:1693` →
`KSW-0002`/`C-0002`. Na pustym tymczasowym katalogu decyzje są:

```yaml
decisions:
  - {action: create_cave, source: PIG, record_number: 2}
  - {action: create_object, source: PIG, record_number: 1, object_id: KSW-0002}
```

`_object_proposal_for_decision` (`staging_review.py:1495–1505`) wybiera
jawne `object_id` przed ID z wiersza, lecz nie sprawdza ich relacji.
Wynik na bazie: `issues=[]`, `written_paths=2`, ślad
`AppliedDecision(action=create_object, record_number=1,
object_id=KSW-0002)`, a finalny pomiar ma `source_ref=PIG:1693` z row 2.
Oczekiwany wynik: błąd tożsamości przed zapisem. Analogiczny selector
`_cave_proposal_for_decision` wymaga sprawdzenia.

Przepis odtworzenia z helperami `tests/test_pig_staging.py`:

```bash
PYTHONPATH=src:tests .venv/bin/python - <<'PY'
from pathlib import Path
from tempfile import TemporaryDirectory
import yaml
from test_pig_staging import _pig_header, _pig_row, StubResolver
from gps_kataster_obiektow_tatr.pig_staging import build_pig_staging, _report_to_json_data
from gps_kataster_obiektow_tatr.staging_review import StagingReports, apply_review_decisions
with TemporaryDirectory() as tmp:
    d = Path(tmp)
    source, target = d / 'pig.csv', d / 'data'
    rows = [
        _pig_row(pig_id='1692', name='Opening One', nr_inwent='T.F-09.33',
                 x_1992='152267,23', y_1992='563744,25', lat='49,23459299',
                 lon='19,87589498', source_year='2010'),
        _pig_row(pig_id='1693', name='Opening Two', nr_inwent='T.F-09.34',
                 x_1992='152267,23', y_1992='563744,25', lat='49,23459299',
                 lon='19,87589498', source_year='2010'),
    ]
    source.write_text('\n'.join([_pig_header(), *rows]) + '\n', encoding='utf-8')
    report = _report_to_json_data(build_pig_staging(
        source, generated_at='2026-05-16T08:00:00Z', data_dir=target,
        prefix_resolver=StubResolver()))
    result = apply_review_decisions(
        {'reviewed_at': '2026-05-16T10:00:00Z', 'reviewed_by': 'reviewer',
         'decisions': [
             {'action': 'create_cave', 'source': 'PIG', 'record_number': 2},
             {'action': 'create_object', 'source': 'PIG', 'record_number': 1,
              'object_id': 'KSW-0002'},
         ]},
        staging_reports=StagingReports(pig=report), data_dir=target,
        initialize_data_dir=True)
    p = target / 'objects/KSW/KSW-0002.yml'
    print([(r['record_number'], r['pig_id'], r['object_id']) for r in report['rows']])
    print([i.code for i in result.issues], len(result.written_paths),
          [(x.action, x.record_number, x.object_id) for x in result.applied_decisions],
          yaml.safe_load(p.read_text())['measurements'][0]['source_ref'])
PY
```

Oczekiwane wyjście na bazie: dwa wiersze z `KSW-0001`/`KSW-0002`,
`[]`, 2 zapisy, `create_object` row 1 → `KSW-0002`, `PIG:1693`.
Wynik powtórzono niezależnie w `TemporaryDirectory`; `data/` repo
pozostało bez zmian.

Przyszła poprawka nie może po prostu zakazać jawnego `object_id`:
`tests/test_staging_review.py:291–340` obejmuje dopuszczalny przypadek
TPN, którego wiersz nie ma jeszcze ID, a kolejność decyzji wymaga
wskazania propozycji. Sprawdzać tożsamość/proweniencję propozycji względem
wiersza i źródła, zachowując ten przypadek.

## Kontynuacja

Utrwalić czerwony test z prawidłowym raportem importera, naprawić
powiązanie wiersza z propozycją, sprawdzić `create_object` i `create_cave`
oraz dopuszczalną ścieżkę TPN. Pełna bramka, mutacje, niezależny review,
push i CI przed wznowieniem PBI-054.
