# PBI-056 — zduplikowane indeksy staging

Data odkrycia: 2026-09-28
Branch: `codex/review-remediation`
Bazowy SHA reprodukcji: `0d8ce8f42c8ba19da30a5d2fce1ed567b0317064`
Status: planowane; **nie implementowano** w sesji PBI-054.
Priorytet: P2 — błędny zapis finalnego YAML po przyjęciu wadliwego raportu.

## Odkrycie

`_tpn_measurements_by_record` (`staging_review.py:1705–1715`) przypisuje
`by_record[record_number] = update` dla każdego wpisu, więc duplikat
`matched_measurements` usuwa wcześniejszą propozycję. `_records_by_id`
(`staging_review.py:1677–1687`) robi to samo dla `proposed_objects` i
`proposed_caves`. Całkowity kształt list jest sprawdzany, lecz duplikaty
indeksów nie są odrzucane przed materializacją decyzji. Finalny katalog
może pozostać poprawny według schematu, dlatego walidacja wyniku nie
wykrywa utraconej propozycji.

W obu potwierdzonych przypadkach raport staging został celowo zduplikowany;
obecne importery nie wygenerowały takiego raportu podczas tego przeglądu.
Raport JSON jest jednak wejściem review, a PBI-040 wymaga blokowania
uszkodzonego wejścia przed zapisem. Żaden plik `data/` w repo nie zmienił
się podczas reprodukcji.

## Reprodukcje na bazie

Uruchom w repo przez `.venv/bin/python` z `sys.path.insert(0, 'tests')`,
używając helperów z `tests/test_staging_review.py` i osobnego
`TemporaryDirectory` dla każdej próby:

1. `_tpn_staging()` daje jeden `matched_measurements` dla wiersza 1.
   Skopiuj wpis `deepcopy`, ustaw w kopii `measurement.elevation_m = 999.0`
   i dopisz go do listy. Przy `add_measurement` TPN row 1 dla istniejącego
   fixture `KSW-0001`/`C-0001` wynik to `has_errors=False`,
   `issues=[]`, dwa zapisane YAML, finalna wysokość `999.0`. Po
   odwróceniu listy finalna wysokość to `1266.0`, również bez błędu.
2. `_pig_staging()` daje propozycję `KSW-0001`. Dopisz jej kopię z tym
   samym ID i `name_local='Different object, same ID'`. Decyzje
   `create_cave` i `create_object` dla PIG row 1 z
   `initialize_data_dir=True` zapisują dwa YAML bez problemu. Finalna
   nazwa to `Different object, same ID`; po odwróceniu listy oryginalna
   `Szczelina pod Gankowa II`.

Pierwszy przypadek można wykonać wprost z repo:

```bash
PYTHONPATH=src:tests .venv/bin/python - <<'PY'
from copy import deepcopy
from pathlib import Path
from tempfile import TemporaryDirectory
import yaml
from test_staging_review import _tpn_staging, _object_data, _cave_data, _write_yaml
from gps_kataster_obiektow_tatr.staging_review import StagingReports, apply_review_decisions
for reverse in (False, True):
    with TemporaryDirectory() as tmp:
        d = Path(tmp) / 'data'
        p = d / 'objects/KSW/KSW-0001.yml'
        _write_yaml(p, _object_data(cave_id='C-0001'))
        _write_yaml(d / 'caves/C-0001.yml', _cave_data(object_ids=['KSW-0001']))
        report = _tpn_staging()
        duplicate = deepcopy(report['matched_measurements'][0])
        duplicate['measurement']['elevation_m'] = 999.0
        report['matched_measurements'].append(duplicate)
        if reverse:
            report['matched_measurements'].reverse()
        result = apply_review_decisions(
            {'reviewed_at': '2026-05-16T10:00:00Z', 'reviewed_by': 'reviewer',
             'decisions': [{'action': 'add_measurement', 'source': 'TPN',
                            'record_number': 1}]},
            staging_reports=StagingReports(tpn=report), data_dir=d,
        )
        saved = yaml.safe_load(p.read_text())
        print(reverse, [i.code for i in result.issues],
              len(result.written_paths), saved['measurements'][-1]['elevation_m'])
PY
```

Na bazie: `False [] 2 999.0` i `True [] 2 1266.0`.

Oczekiwany wynik obu prób: `STAGING_REPORT_INVALID` lub równoważny błąd
jednoznacznie wskazujący duplikat, **0 zapisanych plików**, bez zależności
od kolejności listy. Trzeba osobno sprawdzić także identyczne duplikaty,
`proposed_caves`, fallback z `source_ref` i poprawne unikalne raporty.

## Kontynuacja

Najpierw utrwalić czerwone regresje, potem najmniejsza poprawka wejścia
przed indeksowaniem, zielona pełna bramka, mutacje, niezależny review i
dostarczenie według runbooka. Po PBI-056 przejść do PBI-057; PBI-054
pozostaje zablokowane do zamknięcia otwartych P2.
