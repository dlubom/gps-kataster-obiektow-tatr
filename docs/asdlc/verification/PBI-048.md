## Stan wejściowy i zakres

Lokalny HEAD i `origin/codex/review-remediation` są zgodne (0/0). Bieżący
SHA origin potwierdziło GitHub API, a CI validate poprzedniego checkpointu
[36003630439](https://github.com/dlubom/gps-kataster-obiektow-tatr/actions/runs/36003630439)
zakończyło się sukcesem dla dokładnie tego SHA. `git pull --ff-only` nie mógł
zapisać `.git/FETCH_HEAD` w tym środowisku; porównanie z GitHub API potwierdziło
brak nowego commitu do pobrania.

Zależności PBI-038/040/041/046/047 są dostarczone. Zakres: jawna decyzja dla
TPN `unresolved` z payloadem v2, jej związanie z konkretnym raportem i
tożsamością wiersza, dodanie pomiaru do wskazanego obiektu albo utworzenie
nowego obiektu z prawidłowym powiązaniem jaskini. Finalne `data/` pozostaje
bez zmian; testy używają izolowanych katalogów.

## Reprodukcja

Na bazowym kodzie dwa testy jawnej decyzji dla `unresolved` zakończyły się
**2 failed**: `add_measurement` zgłaszał `STAGING_MEASUREMENT_UPDATE_MISSING`,
a `create_object` — `STAGING_OBJECT_PROPOSAL_MISSING`. Oba przypadki miały
poprawny payload, jawny cel oraz zgodne `record_number`, `GLOBALID` i skrót
raportu. Komenda reprodukcji:

```bash
uv run --frozen --offline pytest -q tests/test_staging_review.py \
  -k explicit_unresolved_row
```

Review wiąże decyzję z kanonicznym SHA-256 całego raportu TPN v2 i tożsamością
wiersza. `add_measurement` kieruje payload do wskazanego istniejącego obiektu;
`create_object` tworzy trwały obiekt w istniejącej jaskini albo nową jaskinię
w tej samej decyzji. Resolver prefixu i zajęte ID, także innych wybranych
propozycji w partii, wyznaczają nowe ID. Wiersze `reject`/`unresolved` i brak
decyzji niczego nie zapisują. Brak celu/payloadu, format v1, zmiana raportu,
GLOBALID lub statusu, podwójny numer wiersza i ponowienie tej samej obserwacji
blokują zapis całej partii. Nowa komenda inspekcji raportu podaje operatorowi
skrót i identyfikatory bez zapisu finalnych danych.
