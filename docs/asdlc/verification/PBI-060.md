## Odtworzenie i skutek

Sekcja `assigned_proposal_provenance`: dwa poprawne wiersze importera
PIG/TPN, row 1 ma już `object_id` i `cave_id`. Przy zachowaniu tych ID:

- zamiana `proposed_objects[0].measurements[0].source_ref` na ref row 2
  zapisuje obiekt row 1 z `PIG:1693` zamiast `PIG:1692` albo
  `TPN:{SOURCE-2}` zamiast `TPN:{SOURCE-1}`;
- zamiana ref jaskini row 1 na ID PIG/NR_INWENT z row 2 zapisuje ten
  błędny identyfikator na jaskini row 1.

Wszystkie propozycje przechodzą JSON Schema. Każdy błędny wariant:
`dry_run_has_errors=false`, `has_errors=false`, dwa zapisane pliki,
0 błędów finalnego walidatora. Poprawne kontrole PIG/TPN także działają.
Selektory `staging_review.py:1497–1499`, `1545–1548` zwracają propozycję
po zgodności ID, pomijając kontrolę proweniencji używaną przy row bez ID.

Sekcja `matched_tpn_provenance`: pomiar ma prawidłowe `source_ref`
zgodne z GLOBALID row 1. Zastąpienie albo usunięcie dokładnego ref TPN
z `object_external_refs`, lub NR_INWENT z `cave_external_refs`, nadal
daje 2 zapisy i 0 błędów, także w dry-run. Kod `1243–1246`, `1316–1320`
sprawdza tylko schemat list ref, nie zgodność z wierszem. Finalny obiekt
może mieć pomiar z jednego GLOBALID i referencję innego źródła.

Kontrole: zły sam `measurement.source_ref` daje
`MEASUREMENT_SOURCE_MISMATCH` bez zapisów. Prawidłowy dodatkowy
`decision.globalid` oraz dodatkowa historyczna ref obiektu przy zachowaniu
dokładnej ref źródła są legalne i przechodzą; nie są częścią znaleziska.
