## Odtworzenie

Na bazowym kodzie schemat `idAssignment` wymagał dla `manual` tekstu
o długości co najmniej 1, więc akceptował same białe znaki. Walidator
zgłaszał `OBJECT_PREFIX_MISMATCH` jako warning, ale nie wymagał powodu
zachowania trwałego prefixu. Testy dodane przed poprawką uruchomiono:

`UV_CACHE_DIR=/tmp/gps-kataster-uv-cache UV_NO_SYNC=1 UV_OFFLINE=1 uv run --frozen --no-sync --offline pytest -q tests/test_validator.py tests/test_schemas.py -k 'id_assignment_requires_documented_reason or manual_id_assignment_schema_requires_nonblank_reason'` — **exit 1, 13 failed, 12 passed**. Dwanaście porażek dotyczyło braku osobnego błędu dla `manual` lub rozbieżności najlepszego pomiaru przy brakującym, `null`, pustym albo białym powodzie; trzynasta pokazała, że schemat akceptuje biały tekst dla `manual`.

Regresja sprawdza `auto`/`manual` × zgodny/niezgodny prefix × brak/`null`/pusty/białe znaki z U+00A0/udokumentowany powód. Wymagany powód daje jeden osobny błąd, a historyczna rozbieżność nadal daje ostrzeżenie. Dwa testy CLI potwierdzają, że błędny rekord blokuje build release i nie zmienia istniejących plików.
