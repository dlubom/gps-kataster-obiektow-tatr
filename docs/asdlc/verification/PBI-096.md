## Implementacja i kontrakt odczytu

- `tpn_api.py`: standardowy urllib, stały endpoint Topografia /6,
  limit odpowiedzi 64 MiB i timeout 30 s. HTTP/transport/JSON/ArcGIS error
  przerywa próbę, również error przy HTTP 200. Duplicate JSON keys,
  NaN/Infinity/overflow i nieprawidłowe struktury są odrzucane.
- Tożsamość Jaskinie/6/Feature Layer/esriGeometryPoint; dokładny zestaw
  nazw i typów 22 deklaracji, 21 atrybutów każdej cechy. Null zachowany,
  daty muszą być integer ms w obsługiwanym zakresie; brak daty jest legalny.
  UUID normalizowane wyłącznie do sprawdzenia unikalności, bajty zachowane.
- `outFields=*`, `returnGeometry=true`, `outSR=4326`, `orderByFields=OBJECTID`.
  Wielkość strony ograniczona limitem usługi. Offset rośnie o rzeczywistą
  liczbę rekordów; krótka strona z true kontynuuje, brak flagi oznacza false.
  Zero postępu z true jest błędem. Każdy punkt musi mieć skończone XY
  w zakresie EPSG:4326. Z/M wymagają nowej polityki. Wspólne XY różnych
  GUID są legalne; ta karta nie rozstrzyga duplikatów terenowych.
- Count i pełne listy OBJECTID przed/po, porównanie posortowanych ID
  każdej strony z pełną listą, unikalność GUID. Dodatkowy odczyt schematu
  po stronach wykrywa zmianę warstwy. Cała próba jest ponawiana od początku,
  domyślnie najwyżej 2 próby, CLI dopuszcza 1–3; bez mieszania odpowiedzi.
- `tpn_snapshot.py`: prywatny staging, wyłączne tworzenie plików/katalogu,
  fsync plików, readback bajtów i protokołu, publikacja manifestu na końcu.
  Kolizja nazwy (także równoczesny zapis) nie nadpisuje dowodów. Błąd zapisu
  sprząta własny katalog; nie powstaje poprawny częściowy snapshot.
- `verify`: bez sieci odtwarza cały manifest z surowych odpowiedzi i porównuje
  jego strukturę/wartości/bajtowe hashe. Nie ufa complete=true. Odrzuca
  dodatkowe/brakujące pliki, symlinki, błędne ścieżki/wersje/typy oraz
  przeliczone hashe fałszywego podsumowania. To wykonywalny walidator
  manifestu; nie wymaga jsonschema jako zależności wykonawczej.

`snapshot_hash`: SHA-256 kanonicznego JSON posortowanego spisu par
`[ścieżka, raw_sha256]`, uzupełnionego parą dla `manifest.json` z SHA-256
kanonicznego manifestu bez snapshot_hash. Manifest zawiera tylko teksty,
całkowite liczniki/ID i bool; bez niejednoznacznej serializacji float.
`files` nie zawiera manifestu. `policy.md` utrwala dokładne bajty całego
kontraktu, a policy_hash wiąże ten plik. Dodatkowa rola `schema_after`
wiąże `layer-after.json`. To doprecyzowania techniczne formatu PBI-095.

## Odtwarzalna próba live

```bash
uv run --frozen --no-sync --offline python scripts/fetch_tpn_snapshot.py fetch \
  --snapshot-id pbi-096-live-20261019 --page-size 500 --attempts 2
uv run --frozen --no-sync --offline python scripts/fetch_tpn_snapshot.py verify \
  data/sources/tpn/snapshots/pbi-096-live-20261019
```

`--offline` dotyczy menedżera zależności uv; `fetch` świadomie czyta publiczne
API. `verify` nie używa sieci. Do nowego odczytu wybierz **nowy snapshot-id**;
próba powtórzenia powyższego fetch po checkoutcie ma odmówić nadpisania.
Nie trzeba historycznego JSON ani zgodności nowych liczników/hashów.

[Zapisany manifest](../../../data/sources/tpn/snapshots/pbi-096-live-20261019/manifest.json)
i 10 powiązanych plików są w Git (około 608 KiB razem): trzy strony,
schemat przed/po, count przed/po, ID przed/po i polityka. Test CI czyta tę
migawkę offline; przyszły fetch waliduje rzeczywisty, a nie historyczny count.

- Przedział: **2026-10-19T12:48:20.879791Z – 12:48:24.203106Z**.
- Strony: offset 0 / 500 rekordów; 500 / 500; 1000 / 35.
- Count przed = po = feature_count = unique_globalid_count = **1035**.
- Pełne zbiory ID przed/po i stron identyczne; schemat przed/po identyczny.
- Snapshot SHA-256: `649961dba9f6dad624aa91fe3c16e0e8da4779607206f2f6e79478da57b8b661`.
- Policy SHA-256: `f09c548ca7b3413befc35af7e1c92b85d019203a4a5a4644b52a7899cc7a1baf`.
- Surowe WER_LOK/UWAGI, null, zero, daty i geometria pozostają bez konwersji.

API nie gwarantuje transakcyjnej migawki atrybutów: kontrola count/ID oraz
schematu nie wykryje każdej równoczesnej edycji wartości. Manifest zapisuje
`count_and_ids_not_transactional_attributes`. Hashe dowodzą treści plików,
nie autentyczności podpisu serwera. `chmod 0444` jest pomocnicze; Git nie
utrwala tych bitów, a niezmienność narzędzia wynika z odmowy nadpisania
oraz readback. Nie deklarujemy odporności systemu plików na utratę zasilania
(fsync dotyczy plików, nie wszystkich wpisów katalogowych).
