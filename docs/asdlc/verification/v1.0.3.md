## Odbiór na GitHub

Kolejność jest obowiązkowa:

1. Commit przygotowania → push `codex/main-remediation-2026-10` →
   [PR #4](https://github.com/dlubom/gps-kataster-obiektow-tatr/pull/4).
2. Potwierdzić zdalny SHA gałęzi i zielony workflow `validate` dla `headSha`.
3. Merge PR do main. Odczytać `mergeCommit.oid`, porównać z `origin/main`
   i poczekać na wszystkie joby `validate` z `event=push`, `headSha=merge SHA`.
4. Dopiero po sukcesie utworzyć annotated tag `v1.0.3` na tym commicie,
   wypchnąć tag i sprawdzić workflow `release` dla tego samego SHA.
5. Odczytać [GitHub Release](https://github.com/dlubom/gps-kataster-obiektow-tatr/releases/tag/v1.0.3),
   porównać notes z changelogiem i sprawdzić komplet sześciu załączników,
   ich SHA-256 oraz zawartość względem katalogu YAML.

Stan PR/tagu/workflow należy odczytać na żywo; ten log przygotowania nie
stanowi samodzielnego potwierdzenia publikacji. Przy odrzuceniu merge przez
reguły GitHuba nie publikować z gałęzi PR ani nie zmieniać reguł bez zgody.
